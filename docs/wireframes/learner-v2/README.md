# Abii V2 — Final learner interface wireframe reference pack

**Status:** consolidated design baseline, not application implementation. All figures, names, timestamps, badge states and photos are illustrative. Dashed artwork areas mark existing official assets or the planned Messenger Abii asset. No new mascot or badge artwork is included. The SVG charts are design references only: implement analytical charts with the existing Apache ECharts package, and retain CSS progress bars.

## How to use
Extract the ZIP, open `index.html` locally in a browser, and open any SVG at full resolution. SVGs are standalone editable vector files. `manifest.json` lists every file, route, viewport and state. Desktop references are generally 1440px wide and mobile references 390px wide; dialogs use their own canvas width. Tall pages represent a continuous scroll document, not a single fixed viewport. Sidebar/header/footer placement is illustrative; preserve existing scroll roots and application shell behavior.

## Eight-phase mapping
1. Global Design System — `01-design-system`; apply approved tokens to all learner routes without restructuring individual layouts.
2. Application Shell, Dashboard & Unified Modals — `02-dashboard`, `09-shared-modals` (shared modal foundation only; specialized consumers in their page phases).
3. My Subjects — `03-subjects`; all five routes, four subject tabs, CRUD and flashcard dialogs in `09-shared-modals`.
4. Review & Quiz — `04-review`; overview, setup, five concrete question formats, feedback, completion, related dialogs. Reuse existing ECharts infrastructure.
5. Progress & Badges — `05-progress`, `06-badges`; badge detail and selector references in `09-shared-modals`.
6. Settings & Profile — `07-settings`, `07-profile`; photo editor and account/data dialogs in `09-shared-modals`.
7. Notification Center & Feedback — `08-notifications`; new mascot asset still required.
8. Global refinement and regression verification — use the entire set; no deployment without approval.

## Binding implementation requirements
- **Brand-only learner buttons (latest revision):** use the existing primary, secondary, outline and ghost appearances for all learner actions. Delete, Remove, Clear History, Delete Materials, Move & Delete and Discard Session use outline/ghost for entry actions and primary pink (`#F8769C`, white text, `#EC658D` hover, `#D9547D` pressed) for explicit confirmation. No separate red destructive button appearance. Preserve semantic warning/error messages, exact labels, confirmations, validation, safe initial focus, pending guards and backend safeguards. Keep the shared `danger` API / `modalDangerClass` compatible where needed; scope visual changes to the learner theme, and preserve Admin/public appearance. This supersedes earlier red-button references and the old learner danger-button styling rule in `docs/design-system.md`; update the actual design-system documentation and showcase in Phase 1. Do not recolor error states or quiz feedback indiscriminately.
- Main #FFF9FC; outer #FFF4F8; secondary / hero #FFE8EF; primary #F8769C; hover #EC658D; pressed #D9547D; white cards #FFFFFF; headings #30262B; muted #6F5964; borders #E8DDE1. Semantic colors remain appropriate for status. White text on primary pink is the user's approved preference and has a known contrast limitation; document it, do not claim WCAG conformance.
- 12-column desktop and 4-column mobile grid; typical page padding 24/16, gaps 16/12, radius 16; responsive min-widths, natural wrapping, equal heights for paired desktop panels. No fixed-height clipping. Simple progress bars remain CSS. Use accessible text equivalents for ECharts.
- Text and existing mascot only in main heroes. Existing artwork is not to be recolored, redesigned or replaced. Messenger Abii is a new asset still to be created using the official reference, solid black oval eyes, white muzzle/chest, three digits per visible paw, half-body or three-quarter crop, envelope held in both paws. No floating prop. Proposed path `public/dashboard-hero/notifications.png`.
- Subjects: Grid/List preference controlled only in Settings. No A–Z control in Subject Folder. Subject Detail retains Name A–Z with equal New Folder/New Topic actions. Topic Folder toolbar has Find a Topic, Topic Order and New Topic; Topic Detail search and Add Flashcard share a row where they fit.
- Dashboard and Progress: preserve three featured badge slots and independent saved selections. Badges: use existing official 18-item catalog, requirement and rarity data. No fabricated counts in actual implementation.
- Notifications: mobile filters remain one horizontal scroll strip; Mark All as Read outside strip; remove all decorative left pink bars; keep unread background, dot, typography and synchronization. Read actions, real destinations, pagination and category mappings stay intact.
- Modal: enhance existing shared component, seven actions, compact mascot header by default, specialized crop header and badge artwork layouts, equal-width footer actions when space permits, single action full width. Desktop flashcard front/back 6:6, mobile stacked; preserve topic selectors and create-topic shortcut. Keep all validation, confirmations and safeguards. Long editors may fill the mobile viewport, with body scrolling and persistent actions; adapt to keyboard/safe area. SVG tall dialog shows full content, not a fixed viewport.
- **Animation freeze:** preserve existing animation files, wrappers, timings, easing, triggers, stagger, page/route transitions, scroll reveals, dropdowns, modals, toasts, skeletons, quiz feedback, confetti, reduced motion. Do not use previously proposed new modal timings. New ECharts chart animation must respect reduced motion and not alter existing motion. Preserve existing backend, database, APIs, authorization, quiz persistence, scoring, mastery, notification producers, Cloudinary integration and admin UI. Never test destructive actions against production data.
- Skeletons are visual geometry references only; unknown values must remain unknown. Empty/error state boards are intended to be placed inside existing panel geometry; do not collapse cards or present failed fetches as zero data.

## Scope and caveats
The exported codebase confirms 13 rendered authenticated learner routes plus `/favorites`, which redirects to `/dashboard`; completion and quiz formats are states of the same quiz route. No separate Favorites or Quiz Completion route is required. Dialogs are grouped by reusable patterns; the implementation agent must inventory all actual consumers and adapt their real fields, labels, validation, and actions. No application code was edited, no runtime behavior was tested, and no production deployment was performed. Final approved conversation decisions override incidental sample copy or drawing differences. The layout is a visual reference, not pixel-perfect production UI.
